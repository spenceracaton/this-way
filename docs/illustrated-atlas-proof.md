# Two-neighborhood illustrated atlas proof

Open `/prototypes/neighborhood-atlas/`. Tap Old Northeast or Crescent Lake to enter the existing illustrated neighborhood map. **Explore nearby** returns to the same atlas camera. This is a small product comparison with the separate continuous discovery prototype.

The atlas presents two broad, named areas and no address pins, count badges, neighborhood pane, or below-map directory. The local view reuses the existing renderer, original artwork, published listing service, and photo cards. Its existing neighborhood name identifies the active map. Only atlas-origin visits get the simple return link and reduced chrome; ordinary entry remains the standard application.

Local display markers use quiet dots with the existing 44 px controls. For pointer taps in overlapping targets, the atlas-origin local map selects the closest actual marker anchor; keyboard and non-pointer activation retain the activated record's identity. This is an opt-in option of the existing renderer, not a new clustering layer.

The two atlas shapes come directly from the original SVG `spotlight` paths, converted through their retained drawing projections. The paths contain only M/L/Z commands, so their vertices are retained with coordinates rounded to six decimals, without stroke expansion. `areas.geojson` retains SVG identifiers and hashes. These are authored illustrated-map areas, not official neighborhood boundaries or submission eligibility geometry. The atlas credits the original OSM artwork geography; its quiet county/road/water context reuses the discovery prototype's existing Census/County/USGS package and source notices. No illustration is warped, joined, or regenerated.

The default season is past Halloween 2026 so the existing public records and approved photos can be explored. Camera return parameters are bounded numeric values pointing only to the fixed local atlas route; they cannot specify an external return URL. Ordinary links, browser Back, and a direct local arrival work without a custom router or new stored state.

Review the actual phone journey: identify a neighborhood as an area, enter its recognizable original artwork in one tap, find a display, close its photo card, return, and choose the other neighborhood. The product questions are neighborhood identity, art prominence, target clarity, and transition burden. Passing layout tests does not establish that this is the final architecture. Physical iPhone gestures and VoiceOver remain unverified.
